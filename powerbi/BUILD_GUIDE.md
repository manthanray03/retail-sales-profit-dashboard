# Power BI build guide

There are two ways to get the report:

- **Quick start (about 10 minutes):** open the ready-made Power BI Project and save it as a
  `.pbix`. Steps right below.
- **Build it yourself (2 to 3 hours):** sections 0 to 11 walk through every step by hand.
  Worth doing once, because it is exactly what interviewers ask about.

Either way, check your numbers against [`expected_values.md`](expected_values.md).

---

## Quick start: open the ready-made project

`Retail_Sales_Profit_Dashboard.pbip` is a **Power BI Project**: the same report as a
`.pbix`, saved as text files so it works with Git. It contains the full data model (8 tables,
10 relationships, date table, sort orders, 52 measures) and all four report pages.
It is generated by `scripts/build_pbip.py` from `measures.dax`.

1. **Use Windows.** Power BI Desktop only runs on Windows (a Windows PC, or Windows in a
   virtual machine on a Mac). Install Power BI Desktop free from the Microsoft Store, or
   update it if it is older than September 2026.
2. **Put the project at `C:\retail-sales-profit-dashboard`** (clone or unzip it there).
   The CSV path in the model points to `C:\retail-sales-profit-dashboard\data\`.
3. **Double-click `powerbi\Retail_Sales_Profit_Dashboard.pbip`.** The report opens with
   empty visuals because a project doesn't store data, only the model.
4. If you put the folder somewhere else: **Home > Transform data > Edit parameters**, set
   **DataFolder** to your `data` folder path, ending with a backslash
   (for example `C:\Users\you\Documents\retail-sales-profit-dashboard\data\`), then
   **Apply changes**.
5. **Home > Refresh.** All four pages fill in. The Year slicer starts on 2025.
6. Compare the cards on the Executive Overview page with [`expected_values.md`](expected_values.md).
7. **File > Save as**, choose **Power BI file (*.pbix)** and save it as
   `powerbi\Retail_Sales_Profit_Dashboard.pbix`.
8. Then do [section 11](#11-export-for-github) (PDF export and screenshots).

**If something doesn't open or a visual shows an error:** Power BI Desktop names the file
and the problem. The usual fixes are updating Power BI Desktop, or removing the one visual
it complains about and re-adding it from the page tables in sections 5 to 8. If the whole
project won't open, use the manual build below with the same `measures.dax`.

**Polish after opening (optional, 15 minutes):** the generated report has the layout,
fields, sorting and slicers, but not every formatting detail. Worth adding by hand:

- Conditional formatting on the Departments matrix and the Stores table (section 6 and 7).
- Data labels or colours you prefer, and alt text on each chart (section 9).
- A map of the stores on the Stores page if map visuals are enabled for you (section 7).

## 0. Before you start

- **Power BI Desktop runs on Windows only.** On a Mac, use a Windows PC or Windows in a
  virtual machine (for example Parallels Desktop). Install Power BI Desktop free from the
  Microsoft Store.
- The CSV files are already in `data/`. You only need to run the Python scripts if you
  change the generator (see the main README).
- Turn off automatic date tables, because this model has its own date table:
  **File > Options and settings > Options > Current File > Data Load >** untick
  **Auto date/time**.

---

## 1. Load the data

1. **Home > Get data > Text/CSV**, pick `data/dim_date.csv`, then click **Transform Data**.
2. Repeat **New Source > Text/CSV** inside Power Query for the other seven files:
   `dim_store`, `dim_department`, `dim_channel`, `fact_sales`, `fact_store_day`,
   `fact_service_desk`, `fact_targets`.
3. Check the data type icon on each column header and fix any that Power BI guessed wrong:

| Columns | Type |
| --- | --- |
| `date`, `month_start` (every table) | Date |
| `*_id`, `year`, `quarter_num`, `month_num`, `year_month`, `iso_week`, `day_of_week_num`, `is_weekend`, `square_feet`, `open_year` | Whole number |
| `units_sold`, `return_units`, `customer_transactions`, `contacts`, `resolved_first_contact` | Whole number |
| `gross_sales`, `markdown_amount`, `net_sales`, `cogs`, `gross_profit`, `return_amount`, `sales_target` | Fixed decimal number |
| `labour_hours`, `total_handle_minutes`, `latitude`, `longitude` | Decimal number |
| Everything else (names, groups, `holiday_event`, `contact_channel`, `contact_reason`) | Text |

4. **Close & Apply.** Loading takes under a minute (about 350,000 rows in total).

## 2. Build the model

### Relationships

Open **Model view**. Delete any relationship Power BI created that is not in this list, then
create the missing ones by dragging the dimension column onto the fact column.

| From (one side) | To (many side) |
| --- | --- |
| `dim_date[date]` | `fact_sales[date]` |
| `dim_date[date]` | `fact_store_day[date]` |
| `dim_date[date]` | `fact_service_desk[date]` |
| `dim_date[date]` | `fact_targets[month_start]` |
| `dim_store[store_id]` | `fact_sales[store_id]` |
| `dim_store[store_id]` | `fact_store_day[store_id]` |
| `dim_store[store_id]` | `fact_service_desk[store_id]` |
| `dim_store[store_id]` | `fact_targets[store_id]` |
| `dim_department[department_id]` | `fact_sales[department_id]` |
| `dim_channel[channel_id]` | `fact_sales[channel_id]` |

All relationships are **one-to-many** with **single** cross-filter direction. The result is a
star schema: dimensions on the outside, four fact tables in the middle, no fact-to-fact links.

### Date table

Select `dim_date` > **Table tools > Mark as date table** > choose the `date` column.
Without this, the PY and YoY measures return blanks.

### Sorting

In **Data view**, select the column, then **Column tools > Sort by column**:

| Column | Sort by |
| --- | --- |
| `dim_date[month_name]` | `month_num` |
| `dim_date[month_year]` | `year_month` |
| `dim_date[day_name]` | `day_of_week_num` |
| `dim_date[quarter]` | `quarter_num` |

### Clean-up

- Set **Summarization: Don't summarize** on `year`, `month_num`, `year_month`, `iso_week`,
  `day_of_week_num`, `store_id`, `square_feet`, `open_year`, `latitude`, `longitude`.
- Data category on `dim_store`: `latitude` = Latitude, `longitude` = Longitude,
  `city` = City, `province` = State or Province.
- Hide the key columns in every fact table (`date`, `month_start`, `store_id`,
  `department_id`, `channel_id`) so report authors use the dimension columns instead.
- Hide the raw amount columns in the fact tables once the measures exist, so every visual
  uses a measure.

## 3. Add the measures

1. **Home > Enter data**, name the table `_Measures`, click **Load**.
2. Open [`measures.dax`](measures.dax). For each measure, select `_Measures`, click
   **New measure**, paste it, press Enter, and set the format listed in its comment.
3. Put each measure in the display folder named in the file (Model view > select the measure
   > Properties > Display folder), e.g. `1 Sales`, `2 Ratios`.
4. Delete `Column1` from `_Measures`.

Quick test before building visuals: drop **Net Sales**, **Gross Margin %** and
**Net Sales YoY %** into a table with `dim_date[year]`. You should see the values in
[`expected_values.md`](expected_values.md), with YoY blank for 2023.

---

## 4. Theme and canvas

- **View > Themes > Browse for themes** > pick `powerbi/theme.json`.
- **Format page > Canvas settings**: 16:9, 1280 x 720.
- Add the same top band on every page: a text box with the page title (left) and a card
  showing **Selected Period** (right, no category label).
- **View > Sync slicers**: sync the Year and Store slicers across all four pages so the
  selection follows the reader.

> One rule for every chart: **one measure per value axis.** Don't use the
> "line and clustered column" combo with two y-axes. When two measures have different
> scales (sales in dollars, margin in percent), give each its own visual.

## 5. Page 1: Executive Overview

**Question it answers:** Are we growing, are we more profitable than last year, and are we
on plan?

| Visual | Fields | Settings |
| --- | --- | --- |
| Slicers (3) | `dim_date[year]`, `dim_store[store_name]`, `dim_channel[channel_name]` | Dropdown style. Year: single select, default 2025. |
| Card (new), one visual | **Net Sales**, **Net Sales YoY %**, **Gross Profit**, **Gross Margin %**, **Gross Margin Change (pts)**, **Target Attainment %**, **Online Share %** | All seven measures in the card's Data well, shown as one row of tiles. Optional: use **Net Sales vs LY Label** and the other label measures as reference labels. |
| Line chart | X: `dim_date[month_name]`; Y: **Net Sales**, **Net Sales PY** | Title "Net sales vs last year by month". Markers on. Data label on the last point only. |
| Clustered column | X: `dim_date[month_name]`; Y: **Net Sales (All Depts & Channels)**, **Sales Target** | Title "Sales vs plan by month". Both measures are in dollars, so one axis is correct. |
| Clustered column | X: `dim_date[year]`; Y: **Net Sales** | X-axis type Categorical. Data labels on. Edit interactions so the Year slicer does **not** filter it (shows all three years). |
| Line chart | X: `dim_date[year]`; Y: **Gross Margin %** | Categorical X axis, markers and data labels on. Same interaction setting as above. Title "Gross margin by year". |
| 100% stacked column | X: `dim_date[year]`; Y: **Net Sales**; Legend: `dim_channel[channel_name]` | Year slicer interaction off. Title "Channel mix by year". |

**Edit interactions:** select the Year slicer, click **Format > Edit interactions**, then
click the "none" icon on the three yearly charts.

## 9. Finishing touches

- **Page navigation:** Insert > Buttons > Navigator > **Page navigator** on each page.
- **Insight text:** add one short text box per page with the main finding (see the README's
  key insights). One sentence, with the number.
- **Alt text:** Format > General > Alt text on each chart, one sentence describing it.
- Rename pages: `Executive Overview`, `Departments`, `Stores`, `Service Desk`.

## 10. Check your numbers

Set the Year slicer to 2023, 2024 and 2025 in turn (all other slicers cleared) and compare
the cards with [`expected_values.md`](expected_values.md). That file also lists the usual
causes when a number doesn't match.

## 11. Export for GitHub

1. Save as `powerbi/Retail_Sales_Profit_Dashboard.pbix`.
2. **File > Export > Export to PDF**, save as `powerbi/Retail_Sales_Profit_Dashboard.pdf`.
3. Take a screenshot of each page (Windows: Snipping Tool) and save them as:
   - `images/powerbi/01_executive_overview.png`
   - `images/powerbi/02_departments.png`
   - `images/powerbi/03_stores.png`
   - `images/powerbi/04_service_desk.png`
4. In `README.md`, delete the `<!--` and `-->` lines around the **Power BI report**
   section so the screenshots show on GitHub.
5. Optional: record a 1 to 2 minute screen video clicking through the slicers and add the
   link to the README.
